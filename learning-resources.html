*------------------------------------------------------------------------------*
* 2.1: Basic Summary Statistics
*------------------------------------------------------------------------------*

// Unpack full distribution moments and shapes
summarize price mpg weight, detail

// Construct customized table of descriptive statistics using tabstat
tabstat price mpg weight, statistics(mean sd min max n) columns(statistics)

// Append specific distribution parameters and percentiles using continuation tags
tabstat price mpg weight, statistics(mean sd min max p25 p50 p75 n) ///
    columns(statistics)

/* The '///' sequence allows line breaks inside long command arguments */

*------------------------------------------------------------------------------*
* 2.2: Statistics by Groups
*------------------------------------------------------------------------------*

// Sort and execute summary tables across discrete sub-populations
bysort foreign: summarize price mpg weight

// Alternative syntax utilizing the inline 'sort' conditional argument
by foreign, sort: summarize price

// Construct structured publication tables grouped by specific variables
tabstat price mpg weight, by(foreign) statistics(mean sd min max n)

// Conduct an independent two-sample t-test comparing group sample means
ttest price, by(foreign)

/* ttest output exposes:
   - Sample parameters across both distinct sub-samples
   - Point estimate of the difference between group means
   - Standard error of the difference and calculated test statistics
*/

*------------------------------------------------------------------------------*
* 2.3: Frequency Tables
*------------------------------------------------------------------------------*

// One-way relative frequency tracking
tabulate foreign

// Expose internal missing counts inside structural distributions
tabulate foreign, missing

// Inspect cell distributions of multi-valued ordered categorical items
tab rep78

// Treat missing states as valid structural cells inside tabulations
tab rep78, missing

*------------------------------------------------------------------------------*
* 2.4: Cross-Tabulations (Two-Way Tables)
*------------------------------------------------------------------------------*

// Build raw two-way conditional matrices
tabulate foreign rep78

// Condition on rows (Row percentages sum up to 100%)
tabulate foreign rep78, row

// Condition on columns (Column percentages sum up to 100%)
tabulate foreign rep78, col

// Extract global cell proportions
tabulate foreign rep78, cell

// Output comprehensive matrix detailing all frequency types simultaneously
tabulate foreign rep78, row col cell

// Conduct Pearson's Chi-Square Test for Independence
tabulate foreign rep78, chi2

/* Chi-Square Test of Independence:
   - Null Hypothesis (H0): Group criteria are independent
   - Alternative Hypothesis (H1): Group criteria are statistically associated
*/

// Report expected cell frequencies under the null hypothesis
tabulate foreign rep78, expected

*------------------------------------------------------------------------------*
* 2.5: Creating Summary Tables
*------------------------------------------------------------------------------*

// Construct analytical summaries over a grouping attribute
table foreign, contents(mean price mean mpg mean weight n)

// Generate a two-dimensional cross-tabulated table of means
table foreign rep78, contents(mean price n)

// Structure professional outputs with custom numeric rounding masks
tabstat price mpg weight length, by(foreign) ///
    statistics(mean sd) format(%9.2f)

*------------------------------------------------------------------------------*
* 2.6: Correlations

/* Correlation Interpretation Matrix:
   - Values trace bound boundaries within [-1, +1]
   - sign denotes direction; absolute value indicates linear strength
*/

*------------------------------------------------------------------------------*

use "plfs.dta"

/* --- 1. USUAL PRINCIPAL STATUS (PS) --- */
/* 
   WHY WE CALCULATE THIS: The Principal Status (PS) measures the activity a person 
   spent the *majority* of their time doing over the last 365 days. It is a long-term 
   measure of labor attachment.
   
   NSSO STATUS CODE LOGIC:
   Codes 11 to 51 = Various forms of employment (Self-employed, Regular wage, Casual labor)
   Code 81 = Unemployed (seeking/available for work)
   Codes 91 to 99 = Out of Labour Force (Students, Homemakers, Pensioners, Children)
*/

/* 
   COMMAND EXPLANATION: In Stata, evaluating an expression in parentheses like 
   (var < 90) returns a 1 if true, and 0 if false. Because all employment codes 
   are below 90, this elegantly creates a binary dummy where 1 = Employed, 0 = Not Employed.
*/
gen lab_for = (prnc_status_code < 90) //labour force ps

/* 
   COMMAND EXPLANATION: We manually assign '2' to those who are strictly unemployed (code 81).
   Now our variable has 1=Employed, 2=Unemployed, 0=Everyone else.
*/
replace lab_for=2 if prnc_status_code==81 //unemployed

/* 
   COMMAND EXPLANATION: We duplicate the variable to safely create a composite categorical 
   variable without destroying our original calculation.
*/
gen lab_comp=lab_for

/* 
   COMMAND EXPLANATION: We isolate students (Code 91) and assign them '3'.
*/
replace lab_comp=3 if prnc_status_code==91 //in education

/* 
   COMMAND EXPLANATION: The `recode` command reorganizes our numbers into a clean, 
   consecutive categorical variable. 
   Old 3 (Education) becomes New 1. 
   Old 1 (Employed) becomes New 2. 
   Old 2 (Unemployed) becomes New 3. 
   Old 0 (Other OLF like homemakers) becomes New 4.
*/
recode lab_comp (3=1) (1=2) (2=3) (0=4) (.=.) , gen(lab_cb) 

/* 
   COMMAND EXPLANATION: We attach text labels to these numbers so our tables are readable.
*/

label value lab_cb lab_cb

/* 
   COMMAND EXPLANATION: The `table` command generates cross-tabulations. 
   - [pw=comb_wt]: Applies the probability weights so the sample scales to the population.
   - stat(fvpercent ...): Tells Stata to output the percentages of the categories.
*/
table  survey (  sector sex) [pw=comb_wt], stat(fvpercent lab_for ) nformat(%5.2f)
table  survey (  sector sex) [pw=comb_wt], stat(fvpercent lab_cb ) nformat(%5.2f)

/* 
   WHY WE CALCULATE THIS: The Indian economy has vast informal and seasonal sectors. 
   A person might be a student for 9 months (PS=Education) but work on a farm for 2 
   months during harvest. The PS+SS framework captures this by "upgrading" anyone 
   who did at least 30 days of economic activity in a subsidiary capacity.
*/

   COMMAND EXPLANATION: Checks if the person has a valid subsidiary employment code (11 to 51).
   Returns 1 if they do, 0 if they don't.

   subsidiary status code (i.e., not missing `!=.`), we forcefully change their

/* --- ESTIMATING UNEMPLOYMENT RATE (UR) FOR PS+SS --- */
/* 
   WHY THIS CALCULATION MATTERS: Graduate students often incorrectly calculate the 
   Unemployment Rate by dividing the unemployed by the *entire* population. 
   Econometrically, UR = Unemployed / (Employed + Unemployed). You MUST exclude 
   students and homemakers, or your UR will be artificially low.
*/

/* 
   COMMAND EXPLANATION: `if age>=15 & (lab_cbpss==2 | lab_cbpss==3)` restricts 
   the denominator. It tells Stata: "Only run this table for people aged 15+ WHO ARE ALSO 
   currently employed (2) or unemployed (3)."
*/
table  sector ( sex   ) [pw=comb_wt] if age>=15&(lab_cbpss==2|lab_cbpss==3), stat(fvpercent lab_cbpss ) nformat(%5.1f) 
// Report match: Rural male (2.7%), Rural female (2.1%), Urban male (4.4%), Urban female (7.1%)

   WHY WE DO THIS: Creating a strict 0/1 binary variable for Labour Force Participation. 
   When a variable is 0 or 1, the mean of that variable is equal to the proportion (rate).

replace lab_forpss=1 if lab_cbpss==2|lab_cbpss==3 // 1 = Employed or Unemployed

   WHY WE DO THIS: Creating a strict 0/1 binary variable for Unemployment. 
   Notice that students/OLF are left as missing (.). They are completely excluded 
   from the calculation.
*/

replace ur_psss=1 if lab_cbpss==3 // 1 = Unemployed

   is highly sensitive to short-term economic shocks and seasonal variations.
   
   Note: CWS has TWO unemployment codes: 
   81 = Sought work
   82 = Did not seek but was available for work (capturing discouraged workers).
*/

   Traditional Unemployment Rates (UR) only capture youth actively looking for jobs. 
   NEET captures youth who are completely detached from both the labor market and 
   human capital accumulation (e.g., discouraged workers, or women doing unpaid domestic work).

   We already categorized the population into 4 groups:
   1 = Education (Code 91)
   2 = Employed (Codes 11-51)
   3 = Unemployed (Codes 81, 82)

   Not NEET (0) = Categories 1 and 2

*/

    statistic(median wage)

    statistic(mean wage)

    c.age c.age2 ///

    i.sex ///
    i.sector ///
    i.state ///
    [pw=comb_wt], vce(cluster state)

estimates store mincer
